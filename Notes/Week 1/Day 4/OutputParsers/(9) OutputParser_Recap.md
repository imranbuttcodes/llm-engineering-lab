# 📖 Output Parsers in LangChain

## What is an Output Parser?

An **Output Parser** is a LangChain component that converts the raw output generated by an LLM into a format that is easier for Python programs to use.

Without an output parser:

```text
User Prompt
      │
      ▼
    LLM
      │
      ▼
Raw Text (String)
```

With an output parser:

```text
User Prompt
      │
      ▼
    LLM
      │
      ▼
Output Parser
      │
      ▼
Python Object
```

Depending on the parser, the final object can be:

* String
* Dictionary
* Pydantic Object

---

# Why do we need Output Parsers?

Suppose we ask:

> Generate information about Python.

Without a parser, the model may return:

```text
Title: Python

Author: Guido van Rossum

Difficulty: Beginner
```

Looks good for humans.

But for Python:

```python
print(result["title"])
```

❌ Error

Because the response is just a string.

Output parsers solve this problem by converting the response into structured Python objects.

# 1. StrOutputParser

## Purpose

Returns plain text.

It performs almost no processing.

---

### Flow

```
Prompt
   │
   ▼
LLM
   │
   ▼
String
```

---

### Example

```python
from langchain_core.output_parsers import StrOutputParser

parser = StrOutputParser()

chain = prompt | model | parser

result = chain.invoke({
    "question": "What is AI?"
})

print(result)
```

Output

```text
Artificial Intelligence is...
```

---

### Return Type

```python
str
```

---

### When to Use

Use when:

* Chatbots
* Story generation
* Essays
* Summaries
* Translation
* General conversations

---

### Advantages

✅ Simplest parser

✅ Fast

✅ No formatting required

---

### Disadvantages

❌ Cannot extract fields

❌ Not suitable for automation

---

# 2. JsonOutputParser

## Purpose

Converts model output into a Python dictionary.

---

### Flow

```
Prompt
      │
      ▼
LLM
      │
      ▼
JSON Text
      │
      ▼
JsonOutputParser
      │
      ▼
Dictionary
```

---

## Without Pydantic

```python
parser = JsonOutputParser()
```

This only tells the model:

> Return valid JSON.

Example output

```python
{
    "title": "...",
    "author": "..."
}
```

The parser does **not** know what keys should exist.

---

## With Pydantic

```python
class Book(BaseModel):
    title: str
    author: str
    difficulty: str
    chapters: list[str]

parser = JsonOutputParser(
    pydantic_object=Book
)
```

Now the parser automatically converts the Pydantic model into a JSON Schema and inserts detailed format instructions into the prompt.

The model is guided to generate:

```json
{
    "title": "...",
    "author": "...",
    "difficulty": "...",
    "chapters": [...]
}
```

---

### Example

```python
parser = JsonOutputParser(
    pydantic_object=Book
)

chain = prompt | model | parser

result = chain.invoke({
    "topic": "Python"
})
```

---

### Return Type

```python
dict
```

Access values

```python
result["title"]
```

---

### Advantages

✅ Works with almost every LLM

✅ Supports JSON Schema

✅ Supports Pydantic

✅ Easy to integrate

---

### Disadvantages

❌ Returns dictionary only

❌ Relies on prompt engineering

❌ Model can still generate invalid JSON

---

# 3. PydanticOutputParser

## Purpose

Converts the LLM response directly into a Pydantic object.

---

### Flow

```
Prompt
      │
      ▼
LLM
      │
      ▼
JSON
      │
      ▼
PydanticOutputParser
      │
      ▼
Pydantic Object
```

---

### Example

```python
parser = PydanticOutputParser(
    pydantic_object=Book
)

chain = prompt | model | parser

result = chain.invoke({
    "topic": "Python"
})
```

---

### Return Type

```python
Book(...)
```

Access values

```python
result.title

result.author
```

instead of

```python
result["title"]
```

---

### Advantages

✅ Strong typing

✅ Automatic validation

✅ Cleaner syntax

✅ Works with Pydantic features

---

### Disadvantages

❌ Still relies on prompt engineering

❌ Not as reliable as native structured output

---

# JsonOutputParser vs PydanticOutputParser

| Feature                       | JsonOutputParser  | PydanticOutputParser |
| ----------------------------- | ----------------- | -------------------- |
| Returns                       | Dictionary        | Pydantic Object      |
| Accepts Pydantic Model        | ✅                 | ✅                    |
| Generates Format Instructions | ✅                 | ✅                    |
| Validation                    | Basic parsing     | Pydantic validation  |
| Access                        | `result["title"]` | `result.title`       |

---

# Native Structured Output vs Output Parsers

This is the most important concept.

Native Structured Output

```python
structured_model = model.with_structured_output(Book)
```

Flow

```
Prompt
   │
   ▼
LLM
(Function Calling)
   │
   ▼
Pydantic Object
```

The LLM itself guarantees the structure.

---

Output Parser

```python
chain = prompt | model | parser
```

Flow

```
Prompt
      │
      ▼
LLM
      │
      ▼
JSON Text
      │
      ▼
Parser
      │
      ▼
Python Object
```

Here the parser **asks** the model to follow the required format through prompt instructions.

# Which One Should You Use?

## Use `StrOutputParser`

When you only need text.

Examples:

* Chatbots
* Stories
* Articles
* Summaries

---

## Use `JsonOutputParser`

When:

* You want a dictionary.
* Your model doesn't support native structured output.
* You're using local Hugging Face models.

---

## Use `PydanticOutputParser`

When:

* You want a Pydantic object.
* You need validation.
* Your model doesn't support `with_structured_output()`.

---

## Use `with_structured_output()`

Whenever your model supports it.

Examples:

* GPT-4
* Gemini
* Claude
* Groq Llama
* Modern tool-calling models

This is the most reliable and production-ready approach because the structure is enforced by the model/API rather than requested through prompt instructions.

# Summary

| Tool                                       | Best For                                                                 |
| ------------------------------------------ | ------------------------------------------------------------------------ |
| **StrOutputParser**                        | Plain text responses                                                     |
| **JsonOutputParser**                       | Returning Python dictionaries from any LLM                               |
| **PydanticOutputParser**                   | Returning validated Pydantic objects from prompt-based structured output |
| **TypedDict + with_structured_output()**   | Simple native structured output                                          |
| **Pydantic + with_structured_output()**    | Production-ready structured output with validation                       |
| **JSON Schema + with_structured_output()** | External/shared schemas and API interoperability                         |
